# 全量回填与增量同步实施设计

本文件细化[读取计划 R12](read-capabilities-plan.md#回填与同步)，以 R11 完整离线读取为基础。交付状态由[实施表](read-capabilities-plan.md#实施状态)记录。目标为管理员选定账户和目录的全部历史、后续新增邮件、标记与删除收敛，以及受支持内容的完整物化。

## 分批交付

| 批次 | 内容 | 验收重点 |
| --- | --- | --- |
| R12A 基础 | V4 事务检查点、扫描与核对协议、可恢复内容工作单元 | 迁移、匹配 tagged OK 后提交、取消/配额/重启、实际文件与索引 |
| R12B 后台接线 | 管理配置、共享调度、全量/增量循环、清理、只读状态 | 多账户公平、前台优先、暂停续跑、dirty 收敛、覆盖进度 |
| R12 协议加速 | CONDSTORE；完整协商后的 QRESYNC/VANISHED | 只读 EXAMINE、MODSEQ、扩展回退和删除核对 |

基础协议必须完整支持 rev1。分批实现期间，未接入运行期的内部基础以合成测试验收；启用入口和实际支持的协议以已合并契约为准。生产同步继续使用 EXAMINE/PEEK。

## 身份、扫描与检查点

每个范围独立绑定 AccountKey、规范目录、UIDVALIDITY、缓存恢复世代、dirty 修订、扫描 ID 和检查点修订。首次成功 EXAMINE 固定 `UIDNEXT-1` 上界；该轮只处理冻结区间，后来到达的 UID 进入独立增量任务。

历史枚举从 UID 1 开始，保留独立断点。新 UID 追踪使用已完成发现上界，定期存在性与 FLAGS 核对使用已缓存 UID 的有界 keyset。三项进度分别保存，历史量大时仍能继续发现新邮件。持久化任务对重复提交幂等，未知结果从最后已提交检查点恢复。

每个 SEARCH 命令最多接收 200 个 UID，完整命令响应最多 128 KiB。空或稀疏区间逐步扩大数值跨度，密集区间保持较小窗口，所有边界用宽整数计算后校验。进度取成功完成的区间上界，即使该区间没有邮件也推进。

只有单条 SEARCH 响应的 UID 数量溢出允许缩小原窗口。关闭原连接，新连接成功 EXAMINE 并核对同 UIDVALIDITY 后，再在原期限和预算内重试；宽度已不超过 200 时仍溢出按协议失败处理。重复 SEARCH、缺 SEARCH、越界 UID、NO/BAD/BYE/EOF、错误 tag、响应字节或解析预算失败均保留原检查点。

一个远端窗口最多暂存 200 个 UID。与本地记录比较时继续按有界页处理，保留窗口身份和本地差分位置；差分完成后才推进主窗口。SQLite 事务保存事实和对应进度，网络等待在事务外。

## 存在性、标记与 dirty 收敛

批量核对只保存所请求 UID 的必要属性，合并同 UID 的拆分响应。显式空 FLAGS 更新为空；UID 出现但缺 FLAGS 作为不完整证据处理。只有匹配 tagged OK 后确认整个目标 UID 缺失，才在原会话 UIDNEXT 范围内登记墓碑。命令失败保留原进度与离线失效状态。

同步专用存储接口可核对 dirty 范围，仍检查管理员范围、账户世代和取消状态。普通离线读取继续遵守 dirty gate。核对在发起 EXAMINE 前取得原 dirty/恢复世代凭据；清除 dirty 时原子复核全部必要进度、恢复世代及无活跃写 claim。期间发生写入、恢复或 UIDVALIDITY 变化时，原凭据失效。目录冻结上界以内的存在性变化更新核对修订，上界之外的新收件进入下一轮。

已确认的 tombstone 在同步与前台之间共享，迟到的旧正证据不能恢复该引用。UIDVALIDITY 变化立即封存旧数据、句柄和游标，为新世代建立独立扫描。移动按旧位置消失、新位置出现处理；缺乏稳定服务端目录标识时，重命名按范围更新与重新同步处理。

## 内容层与完成条件

预算内原始邮件完整保存，并实际物化全部受支持正文、附件及索引。完整 raw 可供派生读取；附件物化完成要求每个附件已完成解码、校验和文件登记。完整正文进入全文索引，预览和输出截断文本沿用各自用途。

原始邮件超限时记录明确 omitted 原因，继续尝试预算内的小正文和附件。部件引用只由服务端生成，沿用 MIME 清单、UID/section/origin 校验、64 KiB 分块和 32 MiB 解码/文件限制。完整协议结束及解码成功后发布文件，失败清理保留原资源所有权。

每个内容步骤取得实际持久化收据后更新检查点。普通前台的有界尽力写入队列继续服务在线请求，后台完成判定使用可靠提交接口。缺失、不支持、超限、配额暂停和可重试故障分别记录，重启后从未完成步骤继续。本地解码、HTML 或索引遇到固定预算上限时，记录该层明确终态；协议与传输故障保留独立重试语义。正文文件写入也按 64 KiB 块检查取消。

范围完成与数据层完成分别计算，绑定扫描 ID、冻结上界和最近核对时间。Facts 任务提交后，完整头、部分头和精确 Message-ID 索引覆盖仍分别报告。`get_cache_status` 展示历史/新增/核对进度，以及 raw、正文、附件、索引的 materialized、derivable、missing、omitted、unsupported 和待处理缺口。配额不足保留扫描与内容任务；增加额度后继续。

## 配置、调度与关闭

管理员通过配置启停后台同步并调整间隔、选定范围和额度，模型只读取状态和已授权内容。旧配置维持原行为；启用方式与迁移随 R12B 一并交付。

后台复用全局调度器，最多占一个执行槽，前台优先。按账户轮转，再在账户内按目录轮转；每完成一个有界扫描批或内容步骤就释放许可，退避、暂停和配额等待期间释放槽位。账户撤销或取消阻止新任务，并保留已完成的短事务。

阻塞文件和 SQLite 工作保留共享执行许可直到实际结束。关闭先停止后台领任务并等待在途工作完成或取消清理，再封闭共享调度、排空写入，按 R11 规则登记清洁运行。慢附件 GET 与后台仍共享全局资源限制。

full 保留已保存的 raw。运行期回收在有界批次中处理孤立、退役和可重建派生内容，保持 pin/lease、物理配额及层状态一致；文件实际删除后才释放额度。主动丢弃 raw 的策略必须同时登记覆盖缺口和重取任务。

## 验收矩阵

| 场景 | 完成依据 |
| --- | --- |
| 历史扫描 | 超过 500 封、多页、空窗口、接近 u32 上界的稀疏 UID 全覆盖，命令数与内存有界 |
| 协议失败 | 数量溢出按规定重连缩窗；重复/越界/错误 tag/NO/BAD/EOF 及预算失败不推进 |
| 增量与核对 | 冻结上界外新邮件在后续轮次出现，FLAGS、删除、移动和 UIDVALIDITY 正确收敛 |
| 持久恢复 | V3→V4 成功与回滚，窗口内重启、提交前后取消、旧检查点 CAS、恢复世代失效 |
| 内容物化 | 中文完整正文可检索，所有附件长度与摘要一致，raw 超限仍保存小部件 |
| 额度与暂停 | 配额耗尽、重启、扩容与管理员暂停后续跑，任务及失败缺口保持 |
| 并发与授权 | 双账户同 UID 隔离，撤权取消，前台优先，批次让出，关闭等待实际资源释放 |
| dirty 核对 | 并发写 claim、迟到 tombstone、标记更新和核对 CAS 保持已知失效状态 |

R13 在完整运行期接线后执行至少 10,000 封合成邮件、持续至少 30 分钟的多账户负载，记录冷/热延迟、IMAP 字节与往返、CPU、RSS、磁盘/临时空间及排队时间。所有附件测试继续使用离线客户端和合成文件。
