# 全量回填与增量同步实施设计

本文件细化[读取计划 R12](read-capabilities-plan.md#回填与同步)，以 R11 完整离线读取为基础。交付状态由[实施表](read-capabilities-plan.md#实施状态)记录。目标为管理员选定账户和目录的全部历史、后续新增邮件、标记与删除收敛，以及受支持内容的完整物化。

## 分批交付

| 批次 | 内容 | 验收重点 |
| --- | --- | --- |
| R12A 基础 | V4 事务检查点、扫描与核对协议、可恢复内容工作单元 | 迁移、匹配 tagged OK 后提交、取消/配额/重启、实际文件与索引 |
| R12B 后台接线 | 管理配置、共享调度、全量/增量循环、清理、只读状态 | 多账户公平、前台优先、暂停续跑、dirty 收敛、覆盖进度 |
| R12C 标记加速 | 独立 V6 水位与 CONDSTORE 生产接线 | 只读 EXAMINE、分页 MODSEQ、取消/重启与 rev1 回退 |
| R12D 删除加速 | 完整协商后的 QRESYNC/VANISHED | 连接级 ENABLE、独立删除水位、范围/事件顺序及预算 |

基础协议必须完整支持 rev1。分批实现期间，未接入运行期的内部基础以合成测试验收；启用入口和实际支持的协议以已合并契约为准。生产同步继续使用 EXAMINE/PEEK。

## 身份、扫描与检查点

每个范围独立绑定 AccountKey、规范目录、UIDVALIDITY、缓存恢复世代、dirty 修订、扫描 ID 和检查点修订。首次成功 EXAMINE 固定 `UIDNEXT-1` 上界；该轮只处理冻结区间，后来到达的 UID 进入独立增量任务。

历史枚举从 UID 1 开始，保留独立断点。新 UID 追踪使用已完成发现上界，定期存在性与 FLAGS 核对使用已缓存 UID 的有界 keyset。三项进度分别保存，历史量大时仍能继续发现新邮件。持久化任务对重复提交幂等，未知结果从最后已提交检查点恢复。

每个 SEARCH 命令最多接收 200 个 UID，完整命令响应最多 128 KiB。空或稀疏区间逐步扩大数值跨度，密集区间保持较小窗口，所有边界用宽整数计算后校验。进度取成功完成的区间上界，即使该区间没有邮件也推进。

只有单条 SEARCH 响应的 UID 数量溢出允许缩小原窗口。关闭原连接，新连接成功 EXAMINE 并核对同 UIDVALIDITY 后，再在原期限和预算内重试；宽度已不超过 200 时仍溢出按协议失败处理。重复 SEARCH、缺 SEARCH、越界 UID、NO/BAD/BYE/EOF、错误 tag、响应字节或解析预算失败均保留原检查点。

发现窗口最多接收 200 个 UID，命中记录与发现上界在同一 SQLite 事务中提交。存在性差分由独立的已知 UID keyset 核对完成：每批最多 200 个 UID，保留冻结上界与本地位置，收到对应 FLAGS 命令的 tagged OK 后才提交该批事实和核对进度。两条进度分别恢复，网络等待在事务外。

## 存在性、标记与 dirty 收敛

批量核对只保存所请求 UID 的必要属性，合并同 UID 的拆分响应。显式空 FLAGS 更新为空；UID 出现但缺 FLAGS 作为不完整证据处理。只有匹配 tagged OK 后确认整个目标 UID 缺失，才在原会话 UIDNEXT 范围内登记墓碑。命令失败保留原进度与离线失效状态。

同步专用存储接口可核对 dirty 范围，仍检查管理员范围、账户世代和取消状态。普通离线读取继续遵守 dirty gate。核对在发起 EXAMINE 前取得原 dirty/恢复世代凭据；清除 dirty 时原子复核全部必要进度、恢复世代及无活跃写 claim。期间发生写入、恢复或 UIDVALIDITY 变化时，原凭据失效。目录冻结上界以内的存在性变化更新核对修订，上界之外的新收件进入下一轮。

已确认的 tombstone 在同步与前台之间共享，迟到的旧正证据不能恢复该引用。UIDVALIDITY 变化立即封存旧数据、句柄和游标，为新世代建立独立扫描。移动按旧位置消失、新位置出现处理；缺乏稳定服务端目录标识时，重命名按范围更新与重新同步处理。

## 内容层与完成条件

预算内原始邮件完整保存，并实际物化全部受支持正文、附件及索引。完整 raw 可供派生读取；附件物化完成要求每个附件已完成解码、校验和文件登记。完整正文进入全文索引，预览和输出截断文本沿用各自用途。

原始邮件超限时记录明确 omitted 原因，继续尝试预算内的小正文和附件。部件引用只由服务端生成，沿用 MIME 清单、UID/section/origin 校验、64 KiB 分块和 32 MiB 解码/文件限制。完整协议结束及解码成功后发布文件，失败清理保留原资源所有权。

每个内容步骤取得实际持久化收据后更新检查点。普通前台的有界尽力写入队列继续服务在线请求，后台完成判定使用可靠提交接口。缺失、不支持、超限、配额暂停和可重试故障分别记录，重启后从未完成步骤继续。本地解码、HTML 或索引遇到固定预算上限时，记录该层明确终态；协议与传输故障保留独立重试语义。正文文件写入也按 64 KiB 块检查取消。

范围完成与数据层完成分别计算，绑定扫描 ID、冻结上界和最近核对时间。Facts 任务提交后，完整头、部分头和精确 Message-ID 索引覆盖仍分别报告。`get_cache_status` 展示历史/新增/核对进度，以及 raw、正文、附件、索引的 materialized、derivable、missing、omitted、unsupported 和待处理缺口。配额不足保留扫描与内容任务；增加额度后继续。

## 配置、调度与关闭

管理员通过配置启停后台同步并调整间隔、选定范围和额度，模型只读取状态和已授权内容。旧配置维持原行为；启用方式与迁移随 R12B 一并交付。

后台复用全局调度器，最多占一个执行槽，前台优先。按账户轮转，再在账户内按目录轮转；每完成一个有界扫描批或内容步骤就释放许可，退避、暂停和配额等待期间释放槽位。账户撤销或取消阻止新任务，并保留已完成的短事务。

阻塞文件和 SQLite 工作保留共享执行许可直到实际结束。关闭先停止后台领任务并等待在途工作完成或取消清理，再封闭共享调度、排空写入，按 R11 规则登记清洁运行。慢附件 GET 与后台仍共享全局资源限制。

full 保留已保存的 raw。运行期回收在有界批次中处理孤立、退役和可重建派生内容，保持 pin/lease、物理配额及层状态一致；文件实际删除后才释放额度。主动丢弃 raw 的策略必须同时登记覆盖缺口和重取任务。

R12B 的派生热缓存使用独立 V5 迁移保存访问顺序，V4 检查点格式保持原样。成功的前台缓存读取更新访问顺序，后台派生验证保持原顺序。回收按最早访问候选选择，在短事务中核对 raw/派生 blob 及访问序号；候选选出后再次被读取时保留副本。旧缓存按迁移时可用的存储顺序初始化，之后由实际读取逐步形成访问顺序。

压力回收先验证同版本原件可重建相同字节，再释放未被租约保护的派生文件。实际释放额度后恢复原受阻任务；主动驱逐的派生层保留可派生状态和物化缺口，在后续重启或扩容时恢复物化，避免当前压力轮反复重建同一副本。清理按有界 keyset 候选页推进，再逐项检查依赖；无可删除行的页面同样保存继续位置。

## 协议加速接入设计

R12B 提供 rev1 生产循环。加速批次按 [RFC 7162](https://datatracker.ietf.org/doc/html/rfc7162) 的 3.1.2、3.1.4、3.1.8、3.2.3、3.2.5 和 3.2.10 实施：CONDSTORE 使用只读 EXAMINE 参数及 CHANGEDSINCE；NOMODSEQ 返回基础核对。QRESYNC 在当前认证连接完成 ENABLE，并收到含 QRESYNC 的 ENABLED 与成功 tagged completion 后才启用。已保存 UIDVALIDITY 与 MODSEQ 绑定同一目录世代；VANISHED 的 EARLIER 与实时响应分别处理。

R12C 将可选 `sync.protocol` 设为 rev1 或 auto，省略保持 rev1；auto 在后台认证连接上探测能力，R12D 进一步优先使用 QRESYNC。前台工具沿用各自既有协议。独立 Delta 阶段复用后台许可和原期限，定期 rev1 存在性审计与 dirty 清除继续运行。能力缺失时复用当前认证连接选择可用协议；扩展命令失败时关闭该连接，在同一期限/累计线路预算内最多建立一次新连接。QRESYNC、CONDSTORE 和 rev1 回退共用该计数，每步骤至多两条实际连接；预算耗尽保留已提交进度供下一步骤继续。状态用固定协议名与降级类别，公开 MODSEQ 时使用十进制字符串。

V6 使用独立的 FLAGS 水位和 FLAGS/删除水位，两者分别推进。基线记录首个 rev1 核对页之前的只读 EXAMINE MODSEQ，并绑定该轮扫描身份；整轮核对成功后才生效。每个增量轮次冻结起始/目标 MODSEQ、UID 上界及范围修订，按最多 200 个已知 UID 分页；每页事实和位置原子提交，末页完成后才提升全范围水位至冻结目标。单个 FETCH 的较大 MODSEQ 只用于处理该页事件，不直接提升全范围进度。基线各页保留本次选择及命令内的显式水位观察；只低于候选、仍覆盖已提交水位时撤销候选并保留已提交值；低于已提交水位或 NOMODSEQ 撤销两条扩展水位及候选。同一轮后来回升也不能重新种入。某页退回无扩展证据的基础协议时，仅撤销当前候选，保留已有已提交水位；候选撤销失败时保留进程内阻断，等待成功持久化。

成员与实质 FLAGS 变化使用持久修订隔离同毫秒竞争，页面自身提交后更新对应证明；冻结上界之外的新 UID 进入后续任务。恢复、dirty、活跃写 claim、撤权或陈旧页面均阻止推进。存储读页、提交和基线登记重新核对当前管理员目录范围，缩小范围并重启后拒绝旧凭据。CONDSTORE 未返回某 UID 时保留该 UID。纯 CONDSTORE 服务器的合法无 UID 异步 FLAGS/MODSEQ 通知可忽略，服务器声明 QRESYNC 时继续要求 UID，即使当前连接没有 ENABLE。成功且一致的 NOMODSEQ 撤销扩展水位，临时协议错误保留已提交点。QRESYNC 使用独立删除水位，防止借用较新的纯 FLAGS 水位漏掉此前删除。

本仓库锁定代码的接口核对（R12A `331775f`）：async-imap 提供 `select_condstore` 和普通 `examine`，需要补只读扩展入口；普通 parser 可解析 VANISHED，当前同步专用有界 parser 尚未接纳该响应。加速批次必须同时实现有界 UID 范围解析、完整 EXAMINE 证据、显式 NOMODSEQ、能力协商与独立版本的持久水位。范围不能展开成无界 UID 数组；CHANGEDSINCE 未返回的 UID 保留原存在性，删除由明确 VANISHED 或基础存在性核对提交。完整差分和水位在同一事务提交，失败回退从原持久点继续。

加速专项覆盖能力缺失/撤回、ENABLE 拒绝或缺 ENABLED、NOMODSEQ、UIDVALIDITY 切换、MODSEQ 回退、超大/重叠 VANISHED 范围、分片响应、错误 tag 和中途断流。继续保留独立 rev1 验收及旧工具回归。

### QRESYNC 生产接线

R12D 在 `auto` 策略中优先使用 QRESYNC。每个后台步骤使用新认证连接，先确认 CAPABILITY，再执行 ENABLE QRESYNC；只有同一连接收到包含 QRESYNC 的 ENABLED 和匹配 tagged OK，才能发出扩展选择或 VANISHED FETCH。协商失败沿原期限、累计传输预算与后台许可回退，实际协议与固定原因进入状态。

完整已知范围至多 200 UID 且非空时，在未选择目录的连接上发送 `EXAMINE mailbox (QRESYNC (uidvalidity modseq known-uids))`。存储预览最多读取 201 UID 用于选择路径，命令中的 known set 始终有界且明确。较大范围使用 ENABLE、只读 EXAMINE CONDSTORE、逐页精确 UID FETCH CHANGEDSINCE VANISHED；空集合使用单独的只读选择证明，跳过 UID FETCH。预览与最终页面按相同目录、世代、范围修订及 UID 序列复核。QRESYNC 生成命令连同 tag、分隔和 CRLF 最多 8192 字节；超限选择有界回退，保留原始已知集合及水位。

VANISHED 保留压缩区间，解析前约束端点位数与区间数；合法倒序端点和同帧重叠规范化为集合。EARLIER 必须属于本命令的精确已知 UID 集合并位于 FETCH 之前；实时删除单独校验本次 UIDNEXT、世代与事件顺序。FLAGS 后发生实时删除时以删除为最终事实，已删除 UID 随后出现 FLAGS 或阶段互相冲突时拒绝收据。

FLAGS/删除使用独立持久水位，同页事实和位置原子提交，末页才提升冻结目标。最后显式 HIGHESTMODSEQ、命令内最低值和 NOMODSEQ 分别保留，两条已提交水位与当前候选共同参与回退判断。已确认的小量实时删除允许覆盖当前页外 UID；数量超过有界提交额度的压缩范围先停止旧范围的离线交付，再持久标 dirty，由新一轮完整 rev1 核对收敛。大范围始终保留压缩形式，核对完成前保留范围围栏及未清洁状态。

前台读取和既有写入口在网络操作之前捕获缓存证据修订。已选择目录的 UID FETCH 收到有界解析成功的实时 VANISHED 帧后，在累计范围和事件顺序校验之前推进对应范围修订并围栏离线读取。整页校验失败、命令失败、中途断流或取消后保留围栏，由 rev1 核对恢复。EARLIER、FLAGS 和页水位仍以匹配 tagged OK 为提交条件。列表、头、清单、raw 和派生内容等正向证据在入队与队列执行时均核对捕获值。修订在核对完成后仍保留，旧请求即使后来返回，也会放弃过期缓存写回；新的请求正常登记。已进入 FIFO 回调的旧写入通过同队列屏障结清，再持久化新的 dirty 修订并开始完整 rev1 核对，使此前尚未缓存的 UID 也进入删除核对。屏障或持久化失败保留离线与 clean 阻断，重试继续处理；负向 tombstone 和世代观察保留原顺序。该进程内机制沿用 V6 格式，正常关闭仍等待队列清空，未清洁重启按既有恢复流程核对。

## 验收矩阵

| 场景 | 完成依据 |
| --- | --- |
| 历史扫描 | 超过 500 封、多页、空窗口、接近 u32 上界的稀疏 UID 全覆盖，命令数与内存有界 |
| 协议失败 | 数量溢出按规定重连缩窗；重复/越界/错误 tag/NO/BAD/EOF 及预算失败不推进 |
| 增量与核对 | 冻结上界外新邮件在后续轮次出现，FLAGS、删除、移动和 UIDVALIDITY 正确收敛 |
| 持久恢复 | V3→V4 成功与回滚，窗口内重启、提交前后取消、旧检查点 CAS、恢复世代失效 |
| 内容物化 | 中文完整正文可检索，所有附件长度与摘要一致，raw 超限仍保存小部件 |
| 额度与暂停 | 配额耗尽、重启、扩容与管理员暂停后续跑，任务及失败缺口保持 |
| 并发与授权 | 双账户同 UID 隔离，撤权取消，前台优先，批次让出，关闭等待实际资源释放 |
| dirty 核对 | 并发写 claim、迟到 tombstone、标记更新和核对 CAS 保持已知失效状态 |

R13 在完整运行期接线后执行至少 10,000 封合成邮件、持续至少 30 分钟的多账户负载，记录冷/热延迟、IMAP 字节与往返、CPU、RSS、磁盘/临时空间及排队时间。所有附件测试继续使用离线客户端和合成文件。
