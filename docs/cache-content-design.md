# 正文与附件持久缓存实施设计

本文件记录 R11 的存储、离线读取、运行代次及验收契约，交付进度见[实施状态](read-capabilities-plan.md#实施状态)。配置与工具入口见[持久缓存设计](cache-design.md)；全量同步继续遵循[读取计划](read-capabilities-plan.md#r10-至-r12-完整本地缓存)。

## 分批交付与职责

| 批次 | 交付 | 模块 |
| --- | --- | --- |
| R11A | V1→V2 存储迁移、文件暂存/发布/租约/回收、分层状态、dirty 修订与核对 CAS | `cache`；真实文件与故障回归；内部 full 入口及 test-only 写入 guard 原型 |
| R11B | full 配置、在线读取写入缓存、显式离线正文/搜索/附件、所有既有写路径失效与运行代次 | `config`、`mail/persistence`、读取及附件适配；写适配集中在 `mail` |
| R11 验收 | 当前权限、字节精确、恢复、失效、配额、取消和完整工具响应预算 | 合成 TLS IMAP、签名 HTTP MCP、认证附件 GET |

R12 负责全部历史回填、增量同步与全范围删除/标记收敛。R11 的状态先精确描述已观察邮件和已保存的数据层。full 的用户入口随 R11B 完整接线开放。

## 文件与数据层

原始邮件、完整正文及单个附件使用独立 artifact 类型。绑定包含 AccountKey、mailbox、UIDVALIDITY、UID，以及正文或 MIME 解析版本；附件保留原 DFS index。每个文件记录服务端生成的 ID、长度及 SHA-256，文件路径不接受客户端或邮件字段。

写入流程为私有暂存文件、分块计算摘要、同步文件、同分区原子无覆盖发布、同步目录，最后在短 SQLite 事务登记引用。网络读取结束并通过 UID/section/origin/tagged completion 后，读取适配器才允许发布。失败或取消保留清理所有权，已经提交的结果在后置诊断失败时仍然有效。派生文件绑定原始内容 ID；替换原始内容时同事务失效旧派生引用，或在同一邮件引用下强制原始内容不可变。

数据库查询文件引用与取得租约在同一临界区内完成，随后在锁外使用同一文件描述符校验长度与摘要，再复核当前引用及 scope gate。离线租约绑定取得时的 scope 修订号和恢复世代；dirty 后即使完成核对，原离线租约和旧离线句柄仍然失效。在线核验后的租约继续绑定完整邮件引用、文件和恢复世代。交付过程中保留租约；dirty、已知世代变化或 tombstone 阻止新读取并终止未完成的旧交付。回收先撤销数据库引用，等待租约归零后删除并同步目录，实际释放文件后再释放磁盘额度。

全局和账户物理配额覆盖数据库、索引、回滚日志、raw、派生文件、暂存、待删及旧分区。暂存文件最多 32 MiB，流式 I/O 使用受限块，不进入元数据的 8 MiB 内存队列。暂存预留与 SQLite 事务预留共用账本。后台工作沿用全局槽位及前台优先策略。

各层区分 materialized、derivable_from_raw、missing、omitted、unsupported，并保存解析版本。完整 raw 可派生附件；附件物化完成需要实际解码并登记文件。raw 超限时允许单独保存预算内的正文或附件，raw 保留明确 omitted 原因。full 保留已完成 raw；空间不足暂停新增保存，允许回收可重建派生副本并更新层状态。

R11 提供有界驱逐与回收的存储接口，启动时清理孤立文件；运行期间由额度限制暂停新增保存。自动回收调度随 R12 后台任务接入，待删和退役内容在实际删除前继续计入物理额度。

## 写操作与运行代次

所有既有写路径在第一个实际副作用之前登记涉及范围。多目录登记在同账户短事务内完成，未观察过 UIDVALIDITY 的目标目录也可登记。每个 scope 保持单调修订号与未完成 claim。结束写操作只结束 claim，dirty 由后续只读核验清除；unknown 保留待核对状态。

标记影响源目录；移动与软删除影响源和目标；草稿 APPEND 影响 Drafts；目录重命名/删除纳入所选子目录。SMTP 在新操作意图落盘后、首次提交之前标记已确认的 Sent 范围；操作键重放继续使用已知结果。缓存登记失败先关闭受影响的离线读取，再按现有邮件写流程返回实际结果。

只读核对以 AccountKey、目录、UIDVALIDITY、恢复世代和 dirty 修订号构成检查点；取得检查点时也在数据库锁内拒绝活跃 claim。完整有界存在性/标记核对成功，且期间没有新 claim 或修订，才用 CAS 清除 dirty。单次 EXAMINE 不清除 dirty。广域收敛交给 R12，同一数据层的覆盖与完成状态随核对更新。

R11 已提供核对 CAS 的存储机制，生产全范围核对任务由 R12 接入。R11 写操作、异常退出或恢复后的受影响目录保持待核对；需要重新积累内容时，可保留原缓存并配置新的私有目录。SMTP 失效范围使用已观察 LIST 中确认的 Sent 角色，服务商未确认位置的自动副本由后续同步核对。

为识别缓存目录不可写期间的在线操作，在账户注册库旁设置独立运行见证文件和生命周期锁，不改变发送操作库。见证包含实例 UUID 与本次运行随机 UUID；所有服务启动，包括 off、metadata 和缓存故障降级，都在开放路由前同步发布新运行代次。见证自身无法可靠持久化时，初始化在 Journal 前结束。

缓存正常关闭的凭据绑定实例 UUID、本次运行 UUID、规范缓存根目录摘要，以及排序后的 AccountKey 命名空间/规范目录范围指纹；账户别名和磁盘额度不进入该安全指纹。下一次启动只有前驱代次与范围相符、本地完整性检查通过且无 dirty 时，才允许立即显式离线读取，随后先持久登记本次未清洁运行状态。已有缓存首次引入见证、跨 off/缓存故障运行、换根、范围变化、见证丢失或异常退出均要求只读核对。全新空缓存从本次成功在线观察建立可读证据。缩小范围后再加入旧目录也重新核对。正常相邻的清洁重启保留离线可用性。

关闭顺序为停止准入、等待会产生副作用的任务与缓存写入结束、检查 claim/dirty/暂存、写入清洁凭据、最后释放运行锁。缓存备份排除运行见证；管理恢复命令推进见证并失效旧内容范围与游标。整体实例回滚仍执行明确的恢复流程。

降级到 R10 等不维护运行见证的旧程序时，在降级前或重新启用 R11 服务前，用 R11 的 `--cache-restored` 维护命令失效旧缓存。旧程序运行期间没有新见证，关闭缓存配置本身不记录其邮件操作；重新升级必须经过这一步恢复核对。

## 显式离线契约

`read_source:live|cache` 默认 live；`search_source:server|cache` 默认 server。默认在线路径继续 EXAMINE 并核对目标存在性。严格 FETCH 在匹配 tagged OK 后确认目标缺失，且 UID 小于当次会话观察的 UIDNEXT 时，立即封存该引用并持久登记 tombstone；覆盖先前 SIZE 成功后的正文、附件和头部读取。范围内尚未保存的 UID 同样留下墓碑，阻止迟到观察重新发布；未来 UID 或缺少 UIDNEXT 时跳过删除登记，其他离线内容继续可用。上界取自原会话，遵循 [RFC 3501 §2.3.1.1](https://www.rfc-editor.org/rfc/rfc3501#section-2.3.1.1)。网络失败保留明确错误，由调用方选择 cache。

| 工具范围 | R11 显式来源与覆盖 |
| --- | --- |
| list_mailboxes / list_emails | read_source；使用已观察 LIST/角色和管理员范围，摘要筛选需有真实 FLAGS、INTERNALDATE、SIZE 和部件证据，缺字段报告覆盖缺口 |
| get_email / get_emails | read_source；保留正文模式、HTML 展示、顺序/重复 UID、逐项错误和完整响应预算 |
| list_attachments / download_attachment / prepare_attachment_download | read_source；完整清单、原 index、内联 Base64、认证 GET 和本地 raw 派生均覆盖 |
| search_emails / locate_message | search_source；全文/头部查询和精确 Message-ID 定位分别有版本化索引 |
| read_conversation | read_source；覆盖原单目录调用与跨目录游标，离线续页/重放只核对本地范围 |
| get_email_status / get_mailbox_statistics / diagnose_connectivity | 保持在线命令语义 |
| list_accounts / get_cache_status / get_operation | 保持各自本地状态及权限语义 |

精确定位和会话共享在线 `ThreadFacts` 的标识规范化，索引分别记录 Message-ID、References、In-Reply-To 的角色及解析版本；检索按目录世代和 UID 数值窗口有界推进。内容副本判定沿用关键原始头和完整 MIME-body 指纹。

离线会话冻结本地 UIDVALIDITY、水位、索引修订及 dirty/恢复世代，token 与 replay 绑定 source，并共用现有游标和输出额度。索引补齐旧 UID 等变动必须使不再稳定的查询重启，或使用同一只读快照。仅本地已索引范围结束时，远端与全部历史覆盖继续报告其已知缺口。缓存分支在在线退避期间也能独立执行，不进入邮箱连接逻辑。

离线结果包含来源、最后在线核对时间、stale、remote_generation_unverified 及范围/层覆盖。当前账户 ACL 在缓存、队列及句柄访问之前验证。缺失、编码不支持和被省略的内容分别报告；缓存标记保留最后观察时间，状态工具继续在线。

完整正文解析后才进入正文索引，预览和响应展示截断结果不进入全文索引。中文长词采用有界 FTS 候选，短词采用有界续查；索引版本和覆盖随结果返回。搜索另有独立范围修订，完整正文索引可见性、筛选证据或头部内容变化使旧搜索游标失效；相同证据重复保存及已撤销数据的物理回收保持修订稳定。查询在读取游标、取得候选和生成最终结果时核对该修订，避免翻页期间补齐旧 UID 后漏掉新匹配。原始邮件派生读取仍遵守现有 MIME、HTML 和字符解码预算。

正文保存规范的完整 UTF-8 内容与有界叶结构信息，读取时再执行选定的 HTML 展示及响应裁减。文件只保存串接文本负载，媒体类型、offset/length 和解析版本放入与 BlobId 同事务绑定的独立 SQLite 元数据；读取前核对叶数量、长度算术、总负载和版本。这样保留单暂存文件 32 MiB 硬限，并避免 JSON 转义膨胀造成完整正文缺失。正文索引绑定这一完整 artifact，结构元数据随引用的替换/回收保持一致。

在线内容捕获使用全局两个载荷许可，各自最多保留 32 MiB；许可贯穿捕获、排队、文件发布和清理。单 FIFO 工作线程转换时最多再持有一个 32 MiB 派生载荷，释放 raw 后再生成渲染文本，三份载荷合计最多 96 MiB；解析器、HTML 和块 I/O 继续受各自预算约束。关闭时同时核对共享调度、本地阻塞任务、附件传输、内容许可、文件租约和 dirty claim，尚有工作则保留未清洁标记。

离线附件准备把 source、账户/目录世代、原附件索引及 artifact 引用绑定到句柄。GET 再检查当前主体、账户授权、dirty/tombstone/世代和文件完整性，cache 路径零 IMAP。live 句柄继续在线核验；改用离线需要申请 cache 句柄。

## 验收矩阵

| 场景 | 检查 |
| --- | --- |
| 缓存写入与正常重启 | 中文/HTML 单封与批量正文，断开模拟后端仍显式 cache 可读；连接计数为零 |
| 默认 live | 同 UIDVALIDITY 下远端删除先在线拒绝，再使离线内容失效 |
| 中文检索 | 头/完整正文长词、1–2 字符、字面转义、有界续查和空页，报告索引覆盖 |
| 附件 | 原始邮件派生与已物化两条路径，重复文件名、原 index、二进制/NUL 的长度和 SHA-256 精确一致 |
| 大邮件中的小附件 | raw omitted，单部件保存和离线 GET 成功，检查没有整封 FETCH |
| 身份与失效 | 双账户同 UID、错误主体、撤权、过期、UIDVALIDITY、tombstone、dirty 和已签发句柄 |
| 写与故障 | 合成 MOVE/APPEND/标记/删除/目录及 SMTP 流程，副作用前 dirty，故障保留原结果 |
| 恢复 | 清洁相邻重启、异常退出、备份恢复、off/failed 运行、换根、见证丢失及初始化失败 |
| 预算与取消 | 全物理配额、暂存/租约释放、坏摘要、取消及事务前后故障；超长转义 RPC id 和完整 wire 预算 |
