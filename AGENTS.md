# Agent working guide

[CONTRIBUTING.md](CONTRIBUTING.md) is the engineering entry point for design, development and maintenance. This file is an execution summary; it does not replace or relax that policy. Read the relevant [architecture constraints](docs/architecture.md) before changing behavior and the [maintenance policy](docs/maintenance.md) before changing dependencies, delivery or operations.

## Working rules

- Rust: Cargo with the pinned toolchain and Cargo.lock; temporary Python scripts: uv; Node tooling: pnpm. Python and Node are not runtime dependencies.
- Keep secrets and deployment identities out of Git and logs. Use synthetic data for regressions. Never send or modify real email for tests without explicit user authorization.
- Test OAuth with isolated clients and users. Source publishing does not authorize production deployment, cutover or rollback; follow the separate deployment procedure.
- Preserve the module boundaries and public contracts in [architecture](docs/architecture.md#module-boundaries). Record material design changes there and follow the compatibility rules in CONTRIBUTING.md.
- Follow the staged [read-capability plan](docs/read-capabilities-plan.md) for attachment delivery, HTML display, Unicode/contracts, multi-account reads, cross-folder conversations and persistent caching. Draft/composition/reply/forward/scheduling enhancements remain deferred. Update current contracts as each work package lands.
- For this read-capability implementation campaign, the primary agent coordinates scope, ownership, integration and acceptance. Delegate execution to `gpt-6.1-sol` with `high` reasoning and `fork_turns=none`; keep file ownership explicit and preserve existing workspace edits. The plan's implementation table is the progress ledger; distinguish implementation, local verification and client acceptance there.

## Constraints to preserve

- Read with EXAMINE/PEEK and retain UIDVALIDITY checks. Keep target-UID FETCH handling, IMAP4rev1 text encoding, APPEND flag syntax and tagged completion checks for SELECT/EXAMINE (including empty mailboxes) and STATUS as specified in [MCP and mail](docs/architecture.md#mcp-and-mail).

- APPEND waits through legitimate untagged notifications for literal continuation; tagged results, BYE and EOF before continuation must fail without sending literal bytes.


- Match raw FETCH results by UID plus required attribute; merge listing attributes per requested UID. Only actual FLAGS attributes replace flags, including empty FLAGS; missing headers must not create blank summaries.
- Bound connections, response bytes and parser allocation. Supply the same application limit to `BudgetStream` and `Client::with_buffer_limit`; transport scanning is not a parser allocation boundary. MIME structure, header and decoding budgets apply before allocation; do not restore `mailparse::parse_mail` on untrusted input. Preserve shared read/forward body selection and bounded tokenizer-only HTML handling, including foreign-content rejection and adjacent-attribute regressions. See [MIME and HTML](docs/architecture.md#mime-and-html).
- BODYSTRUCTURE budgets run inside imap-proto before recursion and allocation, including nested envelopes/extensions, actual owned string capacity and Vec capacity. Preserve Incomplete for split responses and propagate budget Failure through alternatives. async-imap uses the bounded entry point by default; typed limit errors contain no response bytes and terminate further reads/writes. Keep the registry-upstream prefix and lossy-capacity regressions.
- R09 bounded SEARCH is opt-in: cap each command at 128 KiB through its matching tagged completion and at most 200 returned UIDs before result allocation. Bound side-response FLAGS/FETCH allocation before reserving capacity; retain only scalar mailbox notifications in the bounded collector. Require an explicit SEARCH response, keep pre-command search/completion data out of the new result, and preserve the post-completion buffer for subsequent commands. Typed limit and protocol failures close the bounded command stream. Keep ordinary SEARCH/FETCH behavior and the patched dependency provenance intact.
- Treat explicit unsupported Content-Disposition types as attachments across body selection, discovery and downloads; preserve absent/empty and inline semantics, filename detection and multipart subtree pruning.
- Plain-only alternative probes must cover the complete inline representation: non-empty HTML makes the candidate incomplete, and all collected fragments must be rolled back before trying another candidate.
- Validate transfer-encoding support before interpreting an entity or decoding a leaf; unknown encoded multipart content stays opaque, and downloads must not label raw encoded bytes as decoded content.
- Persist intent before SMTP. Preserve accepted/unknown outcomes across journal or cleanup failures; never automatically retry unknown sends. Keep the documented principal-scoped operation keys, bounded QUIT cleanup, TLS/AUTH and SMTPUTF8/8BITMIME policy. Preserve the canonical draft-header privacy boundary and body bytes. See [send lifecycle](docs/architecture.md#send-lifecycle).
- Validate DATA source bytes before journal claim: CRLF line boundaries, no NUL and at most 998 source octets per line before dot-stuffing. Preserve supported MIME body bytes; reject unsupported formats without connecting or reserving the operation key.

- SMTPUTF8 requirements include raw internationalized headers at every MIME level, including attachments; encoded-words and 8-bit bodies alone do not require it. Refuse missing SMTPUTF8 before MAIL and persist that definite refusal as rejected.
- Authenticate every HTTP request entering MCP. Preserve issuer, audience, expiry, nbf, scope and subject validation, the hard JWKS TTL and shared refresh cooldown. Keep deployment-specific OAuth and login-asset checks in [authentication](docs/architecture.md#authentication).
- Count the complete serialized JSON-RPC tool response, including the actual id, request_id, structuredContent and escaped text copy. Keep the 1024-byte serialized-id guard ahead of rmcp; bounded fallback must retain known send status and direct clients to `get_operation` with the original key. See [stable contracts](docs/architecture.md#stable-contracts).
- Fit `get_email` display-body prefixes against that complete wire budget at UTF-8 boundaries; preserve existing truncation flags and metadata, and retain LIMIT_EXCEEDED when metadata alone cannot fit.
- Keep the vendored dependency provenance, completion-status regressions and `scripts/audit-dependencies.sh` aligned. Plain `cargo audit` skips path packages. Audit both pinned upstream identities and reject unmapped path/git dependencies. Keep the Docker context allowlist limited to async-imap and imap-proto. See [dependency maintenance](docs/maintenance.md), [async-imap patches](vendor/async-imap/PATCHES.md) and [imap-proto patches](vendor/imap-proto/PATCHES.md).

- Mail workflow extensions live in `mail/attachments.rs` and `mail/insights.rs`; reuse bounded MIME and rev1 text handling. Keep attachment indices consistent and preserve inline Base64 downloads; authenticated binary handles use a separate tool.
- PartManifest preserves the original DFS leaf/subtree-root indices across raw MIME and BODYSTRUCTURE. Verify complete MIME headers for every visited node before publishing indices; duplicate metadata, Base64/QP multipart and missing multipart boundary require raw fallback. Finish a separate SIZE command before allowing one fresh-connection raw fallback; preserve the original deadline and UIDVALIDITY checks. Match required MIME headers by UID, section and origin under shared header/command budgets. Keep successful fallback diagnostics fixed and private, and treat header/raw protocol failures as terminal.
- Attachment IDs bind AccountKey, mailbox, UIDVALIDITY, UID and the original MIME traversal index; preserve id/index agreement. Download errors use bounded private JSON and release transfer permits on every failure or cancellation. Generate digests from fully decoded bytes after successful tagged completion; retain the same-subject and current-account checks on GET.
- R07 attachment reads use server-generated sections and bounded partial FETCH commands. Check literal limits before allocation and match UID/section/origin plus tagged completion before advancing. Incremental decode and staging share a 32 MiB decoded limit; publish a file only after full decode and protocol completion. Preserve ownership of file and transfer permits through pending filesystem work, response consumption and cancellation cleanup. Staging is private, instance-scoped and limited to four files; startup recovery only cleans recognized files under the locked staging directory.
- Body reads share the raw MIME candidate selector and decoded-body/HTML budgets. Preserve full-body validation before display truncation, cross-chunk charset state and bounded UTF-7 raw fallback. Track command completion separately from error codes: completed local failures may continue a batch, while header/body protocol failures terminate it. Repeated batch UIDs retain ordered per-input results with at most one raw fallback per UID; all replacements retain the original deadline and UIDVALIDITY. MIME header line and byte budgets span the entire verified tree.
- Listing previews are opt-in and retain completed summaries, classifications and cursors on per-item failures. Share 8 KiB encoded sampling per message and 128 KiB per page, including probes, and emit at most 200 Unicode code points. Partial transfer/charset/HTML input must not be flushed as complete content. Full-wire fitting removes optional preview fields, including statuses when necessary, before rejecting a base summary page. Classify only completely observed header fields with fixed rule signals; never visit unsubscribe URIs. Attachment filtering uses verified manifests and at most one bounded raw fallback per page, retaining UIDVALIDITY, deadline, aggregate transport budget and last-examined cursor.
- Attachment acceptance is currently offline only: synthetic files and local simulated IMAP/MCP clients. Defer real ChatGPT connections and real-mail testing. Describe the user-facing behavior as downloading attachments and reading their contents. Preserve byte-exact fixtures through Git attributes.
- Multi-account reads authorize the current principal before queueing, cache access or connections. Keep legacy writes bound to the original default and get_operation available by principal/key after mailbox ACL removal. Share backend, attachment and header-cache quotas globally; include AccountKey in cache and attachment references. Validate all account configuration and registry migration before opening Journal, preserve the original default UUID and retain generation/tombstone history.
- Cross-mailbox conversations freeze folder scope, UIDVALIDITY and high UID; exact identifier matching follows bounded per-field/per-folder SEARCH windows. Share page-wide candidate, result, body, command, connection and time budgets. Compare raw critical headers and complete versioned MIME-body fingerprints before collapsing locations; preserve collision/unverified variants. Authorize before cursor access, count leased state in the global 64-slot/8 MiB quota, and keep locks off network waits. Fit the actual wire response and next token before atomically committing delivery; cancellation retains undelivered items. Replay preserves the committed page metadata and rechecks all frozen folders; stale generations invalidate the cursor. Keep raw fallback ownership keyed by full message reference, including mailbox.
- Persistent cache follows [cache design](docs/cache-design.md): default off, explicit administrator scopes, private ownership-checked account partitions, independent SQLite files and physical global/per-account quotas including journals and retired data. Authorize before access; observed generations immediately fence old evidence. Metadata writes use bounded queued work and preserve successful live results. Durable cursors retain global state quotas, bounded versioned decoding, atomic state/replay CAS and original expiry across restart; configured storage failures must not silently downgrade them to memory. Preserve known commits across post-commit diagnostics, and keep restore/dirty handling independent of the send journal.
- Full-cache storage follows [content-cache design](docs/cache-content-design.md): versioned artifacts bind the full message reference; keep derived artifacts consistent with raw content identity through corruption recovery and GC. Charge stage, journal, pinned and pending-delete bytes until physical release; validate the same file descriptor before delivery and retain lease ownership through cancellation. Dirty claims cover all affected configured scopes before mutation; reconciliation stamps require no active claim both at capture and CAS. Bind reconciliation stamps and offline leases to the relevant instance, generation and revision so old offline references stay invalid after reconciliation.
- Advance the independent account-registry-side runtime witness before Journal or routes on every startup, including off and cache-failure runs. Clean receipts bind the adjacent run, cache root and selected account/mailbox scopes. Admit writes before queueing, seal and drain their ownership before a clean shutdown, and preserve actual SMTP outcomes through cache failures. Restore and pre-witness downgrade procedures are in [deployment](docs/deployment.md#持久缓存备份与恢复).
- Explicit cache reads authorize before local work, perform zero IMAP, share the global 4-slot/20-request admission bounds, and retain permits through cancelled blocking work. Preserve live source defaults, target-existence checks, source-bound cursors and offline scope/revision checks. Store complete body text separately from bounded metadata within the 32 MiB artifact limit; index only complete canonical content. Report missing FLAGS and other observations as unknown with coverage and timestamps.
- Cache conversation commits recheck pending live tombstones for every frozen scope at the final SQLite commit gate; retain the prior token and replay on refusal. Keep this gate separate from live cursor validation. Completed commands confirming a missing target UID invalidate its verified cache reference only below that session's observed UIDNEXT, including later body/attachment reads after an earlier successful SIZE. Preserve durable tombstones for unseen UIDs within that bound to fence delayed observations; skip future UIDs and missing UIDNEXT without disabling offline reads. Attachment-selection errors and protocol failures retain their distinct handling.
- Synchronization follows [the R12 design](docs/cache-sync-design.md). Keep independent history, new-UID and known-UID reconciliation checkpoints under frozen account/mailbox/UIDVALIDITY/high-UID/restore/revision identities. Commit facts and progress only after matching tagged completion; content progress requires an actual durable receipt. Bound search and local differences, shrink only genuine UID-count overflow, and retain gaps across quota pauses and restart. Background batches share admission, release slots before backoff and preserve ownership through cancellation; dirty clearing requires complete verification and a final no-active-claim CAS.
- Background synchronization requires explicit full-mode administrator configuration; omitted sync configuration remains paused. Revalidate configured scope, current AccountKey, effective read authorization and cancellation before queueing and connecting. Interleave history, tail, reconciliation and content work; quota pauses retain remote change checks. Report frozen-range discovery, FLAGS/existence verification, complete headers, exact-ID indexes and materialized content separately. Keep published migrations immutable and add a new schema version for later format changes.
- CONDSTORE is opt-in through sync.protocol=auto; default rev1 and periodic existence reconciliation remain. Seed extension watermarks before the first page of the same complete rev1 audit, bind them to scope/restore/dirty revisions, and commit each bounded UID page with its facts. Advance the committed watermark only after the last page to the frozen target. Omitted CHANGEDSINCE UIDs remain present; explicit NOMODSEQ or an observed rollback below the committed or candidate watermark invalidates it before persistence, including the in-process clean-shutdown fence. Keep the minimum explicit command watermark as well as its final value; a plain-protocol fallback revokes only the incomplete seed and retains committed lanes. Recheck the current configured namespace/mailbox scope for old scans and delta pages. Keep FLAGS and future QRESYNC deletion lanes independent, and serialize public MODSEQ values as decimal strings.
- Statistics require all requested STATUS fields and matching tagged completion. Batches preserve per-item unknown/unprocessed outcomes and never retry automatically; document bounded search coverage and omissions.
- On the `get_emails` raw fallback path, continue after local MIME errors only after raw FETCH completed successfully. Keep the conservative stop on raw fetch/transport/protocol failures; later items remain unprocessed, never automatically retried.

## Before handing off

- Publish each completed work package through a PR, inspect code-review feedback and final-head CI, resolve findings, then merge to main. Keep the local checkout and remote refs synchronized while preserving ongoing work on its branch.
- Follow the applicable validation and PR checklist in CONTRIBUTING.md; preserve the [invariant-to-verification mapping](docs/architecture.md#invariants-and-verification) when behavior changes.
- For a coordinated issue repair campaign, keep per-issue assessment, PR, independent review and merge evidence in [ISSUE_PROGRESS.md](ISSUE_PROGRESS.md). Review the final PR head and its required checks after integration updates; source merges do not authorize deployment.
- Keep current contracts in README/architecture, maintenance procedures in their designated guides, and dated results in [validation](docs/validation.md) with a commit or release reference. Track remaining work through [open follow-ups](CONTRIBUTING.md#待闭环事项) and issues, not Completed/TODO entries in this file.

- 0.2.1 uses larger bounded capacities (32 MiB message, 128 MiB connection, 2 MiB tool response). Keep the complete-wire budgeting for single and collection display bodies. Conversation local failures may continue only after the corresponding IMAP command completed; expose skipped candidates and message errors. Maintain the 4-slot/20-request admission bounds and the 1 GiB deployment memory allowance when adjusting these capacities.
