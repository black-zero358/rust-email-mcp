# Agent working guide

Start with [CONTRIBUTING.md](CONTRIBUTING.md). Read the relevant design and its [verification map](docs/architecture.md#invariants-and-verification) before changing behavior. Follow [maintenance](docs/maintenance.md) for dependencies and releases.

## Work and delivery

- Use one branch and PR per work package. Keep changes scoped, preserve existing edits, and follow the [review and CI gates](CONTRIBUTING.md#验证与完成标准). Check main CI after merging and sync local and remote refs. Restore a red main before merging more.
- Use the pinned Rust toolchain and Cargo.lock, uv for temporary Python, and pnpm for Node. For exact-source validation, use a per-snapshot Cargo target. If reusing a target, clean this package and both vendored packages in each profile, including `cargo clean --release` for release. Record source and binary digests.
- Use synthetic mail and isolated OAuth clients and users. Keep secrets, mail content and deployment identities out of Git and logs. Real mail writes and production deployment, cutover or rollback require separate authorization. See [deployment](docs/deployment.md#验收与回滚).
- Keep README focused on setup and distinguish main from tagged downloads. Record routine evidence in the PR, milestones in the [read-capability plan](docs/read-capabilities-plan.md#实施状态) or [issue campaign ledger](ISSUE_PROGRESS.md), and reusable evidence in [validation](docs/validation.md). Track follow-ups in [CONTRIBUTING](CONTRIBUTING.md#待闭环事项) or issues.
- For the read-capability campaign, the lead owns scope, integration and acceptance. Delegate execution to `gpt-6.1-sol` at high effort with `fork_turns=none` and explicit file ownership. Track implementation, local verification and client acceptance separately. Attachment acceptance is offline. Draft, reply, forward and scheduling enhancements remain deferred.
- Keep the compact test suite below 20% of the 42873c0 baseline in source lines, bytes and Rust cases, measured by `uv run scripts/test-inventory.py`. Maintain representative regressions through production entry points and update the architecture verification map when replacing tests. Use [commit-bound packaging](docs/maintenance.md#发布检查) with its isolated recovery smoke test for release candidates. Label prebuilt packages as snapshots.

## Read before changing these areas

| Area | Rules and owning documents |
| --- | --- |
| MCP and OAuth | Preserve [module boundaries](docs/architecture.md#module-boundaries), [tool contracts and full JSON-RPC budgets](docs/architecture.md#stable-contracts), and [authentication](docs/architecture.md#authentication) on every MCP request. Keep the actual ID, structured result and escaped text copy in wire accounting. |
| IMAP, MIME and attachments | Use EXAMINE/PEEK, UIDVALIDITY and matching tagged completion. Match UID and required attributes, including section/origin for partial fetches. Bound parsing and decoding before allocation. Preserve stable attachment indices, private staging and bounded raw fallback. A batch may continue after a local content error only when the corresponding IMAP command completed successfully. See [MCP and mail](docs/architecture.md#mcp-and-mail) and [MIME and HTML](docs/architecture.md#mime-and-html). |
| SMTP and drafts | Validate DATA before claiming the operation key and persist intent before SMTP. Preserve accepted and unknown outcomes through cleanup and never automatically retry unknown sends. See [send lifecycle](docs/architecture.md#send-lifecycle) for privacy, encoding and capability rules. |
| Accounts and conversations | Authorize before queueing, cursor/cache access or connecting. Preserve legacy default-account writes, principal-scoped operation lookup, and shared admission limits. See [multi-account design](docs/multi-account-design.md) and [cross-mailbox conversations](docs/architecture.md#cross-mailbox-conversations). |
| Cache and sync | Default off, explicit scopes, zero IMAP for cache reads. Preserve generation fences, runtime witness before Journal, durable cursors and dirty-state recovery. Keep published migrations immutable, rev1 as the default, and CONDSTORE/QRESYNC opt-in. See [cache design](docs/cache-design.md), [content cache](docs/cache-content-design.md), [sync design](docs/cache-sync-design.md) and [restore](docs/deployment.md#持久缓存备份与恢复). |
| Vendored dependencies and probes | Use `scripts/audit-dependencies.sh` to audit both pinned upstream identities. Preserve the Docker allowlist and patch regressions. See [async-imap](vendor/async-imap/PATCHES.md), [imap-proto](vendor/imap-proto/PATCHES.md) and the [attachment fixtures](tests/fixtures/attachment_delivery/README.md) for the current Rust byte-exact regression. The former offline client probes are retained in Git history. |
